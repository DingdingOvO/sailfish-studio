01-environment-setup.md

01 - 开发环境搭建

概述

本文档指导开发者搭建 Sailfish Studio 的本地开发环境。

系统要求

· 操作系统: macOS 12+ / Windows 10+ / Ubuntu 20.04+
· 内存: 16GB+ 推荐
· 磁盘: 50GB+ 可用空间

安装步骤

1. Rust

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
rustup default stable
rustup target add wasm32-unknown-unknown
```

2. Node.js & pnpm

```bash
# 使用 nvm
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash
nvm install 24
nvm use 24
corepack enable pnpm
```

3. wasm-pack

```bash
cargo install wasm-pack
```

4. Emscripten (用于 C/C++ 扩展编译)

```bash
git clone https://github.com/emscripten-core/emsdk.git
cd emsdk
./emsdk install 4.2
./emsdk activate 4.2
source ./emsdk_env.sh
```

5. Tauri CLI (桌面端开发)

```bash
cargo install tauri-cli
```

6. 其他工具

```bash
cargo install cargo-nextest cargo-audit cargo-tarpaulin cargo-fuzz
pnpm add -g @biomejs/biome @playwright/test
```

克隆仓库

```bash
git clone https://github.com/Sailfish-Studio/sf-core.git
git clone https://github.com/Sailfish-Studio/sf-editor.git
# ... 其他仓库
```

验证安装

```bash
cd sf-editor
pnpm install
pnpm build
pnpm dev
```

访问 http://localhost:3000，看到编辑器界面即表示成功。

02-project-structure.md

02 - 项目结构与模块职责

概述

Sailfish Studio 采用 Monorepo 架构，6 个主仓库，内部通过 workspace 管理 80+ 细粒度包。

仓库总览

仓库 包数 职责
sf-core 28 核心运行时、引擎、语言工具链
sf-editor 13 编辑器 GUI、UI 框架、插件、社区
sf-tools 8 打包器、CLI、工具
sf-services 6 云端服务
sf-extensions 21+ 扩展市场与内容
sf-docs — 文档站

关键模块依赖关系

· sf-editor → sf-core (通过 Wasm 导入)
· sf-editor → sf-tools (打包功能调用)
· sf-extensions → sf-core (扩展运行时依赖)
· 桌面端 → sf-editor (WebView 加载) + sf-core (sidecar 子进程)

03-coding-standards.md

03 - 编码规范

Rust 规范

· 格式化: cargo fmt --check
· Lint: cargo clippy -- -D warnings
· 禁止 unsafe (除非审查批准并附注释)
· 禁止 unwrap() / expect() (使用 ? 或显式错误处理)
· 禁止魔法数字 (必须定义为具名常量)
· 所有公共 API 必须有文档注释 ///
· 测试覆盖率 ≥ 95%

TypeScript 规范

· 格式化 & Lint: Biome
· 禁止 any 类型 (除非审查批准并附注释)
· 禁止魔法数字
· 所有公共函数必须有 JSDoc
· 测试覆盖率 ≥ 95%

命名规范

· Rust: snake_case 函数/变量, CamelCase 类型, SCREAMING_SNAKE_CASE 常量
· TypeScript: camelCase 函数/变量, PascalCase 类/组件, SCREAMING_SNAKE_CASE 常量

01-sf-vm-api.md

01 - sf-vm WASM 导出接口

概述

sf-vm 编译为 WebAssembly 后，导出以下函数供 JavaScript 调用。

函数列表

sf_vm_create() -> u32

创建新的 RuntimeState，返回指针句柄。

sf_vm_execute(handle: u32, opcode: *const u8, opcode_len: u32, args_json: *const u8, args_len: u32) -> u64

执行积木操作。opcode 为 UTF-8 字符串，args_json 为 JSON 格式参数。返回值高 32 位为错误码 (0 成功)，低 32 位为结果指针。

sf_vm_destroy(handle: u32)

销毁 RuntimeState，释放内存。

sf_vm_compile(handle: u32, project_json: *const u8, json_len: u32) -> u64

编译项目，返回 JS 代码字符串指针。

sf_vm_get_variable(handle: u32, var_name: *const u8, name_len: u32) -> u64

获取变量值。

sf_vm_set_variable(handle: u32, var_name: *const u8, name_len: u32, value_json: *const u8, value_len: u32) -> u32

设置变量值，返回 0 成功。

05-performance-tuning.md

05 - 性能调优

Wasm 内存优化

· 使用 wasm-opt -Os 压缩
· 启用 wee_alloc 轻量分配器
· 资源懒加载，避免全量加载到 Wasm 内存

渲染性能

· 使用 WebGL 批量绘制 (按纹理排序)
· 脏矩形检测避免全画布重绘
· 克隆体使用对象池

CDN 缓存策略

· 静态资源: max-age=31536000 (一年)
· HTML 文件: max-age=0 (每次验证)
· API 响应: max-age=60 (1 分钟)

数据库查询优化

· 积木树查询使用预编译语句
· 资源 BLOB 仅在需要时读取
· 定期 VACUUM 清理碎片

03-sfl-guide.md

03 - .sfl 语言指南

概述

.sfl 是 Sailfish Studio 的纯文本编程语言，与积木一一对应。可以用文本编辑器编写，然后在编辑器中导入为积木，也可以直接通过 SF Runtime 运行。

变量与类型

```
var score: number = 0          # 双精度浮点数
let name: string = "Player"    # 字符串
const MAX: number = 100        # 常量
var flag: bool = true          # 布尔值
var items: list<number> = [1, 2, 3]  # 列表
var player: struct { name: string, hp: number } = { name: "Hero", hp: 100 }
```

控制流

```
if score > 100:
    broadcast "win"
else:
    broadcast "continue"

repeat 10:
    this.moveSteps(10)

forever:
    this.nextFrame()
```

函数

```
func greet(name: string) -> void:
    this.say("Hello, " + name)

func add(a: number, b: number) -> number:
    return a + b
```

广播

```
broadcast "game_start"
broadcast "game_over" and wait

on "game_start":
    this.show()
```

06-faq.md

06 - 常见问题

性能相关

Q: 项目运行卡顿怎么办？
A: 尝试以下方法: (1) 减少克隆体数量 (2) 使用加速模式 (3) 在菜单中运行“优化所有资源”压缩素材 (4) 检查内存仪表盘是否超过限制。

Q: 大文件导入很慢？
A: 图片超过 10MB 时会收到警告。建议在导入前压缩图片 (编辑器内置一键优化功能)。

文件相关

Q: .sf 和 .sb3 有什么区别？
A: .sf 是 Sailfish Studio 的新格式 (SQLite 数据库)，比 .sb3 (ZIP) 更紧凑，支持实时保存和增量写入。Sailfish Studio 同时兼容 .sb3 和 .sb2。

Q: 如何将 .sb3 项目转为 .sf？
A: 在编辑器中打开 .sb3 文件，然后“另存为”选择 .sf 格式即可。

协作相关

Q: 协作时冲突怎么办？
A: 积木树冲突自动解决。变量以最后写入为准。造型编辑期间锁定，不会产生冲突。离线编辑后恢复连接时如有冲突，系统会弹出对话框让您选择保留哪个版本。

Q: 最多多少人同时协作？
A: 单个房间最多 32 人。

扩展相关

Q: 如何开发扩展？
A: 参考扩展开发文档 (API 参考)，使用 JS、Rust 或 C++ 编写，提交到扩展市场。

Q: 社区渠道的扩展安全吗？
A: 社区渠道的扩展未经官方审核，可能包含风险。请谨慎安装，或在安装前查看社区评价。

桌面端相关

Q: 桌面版和 Web 版有什么区别？
A: 功能基本一致。桌面版支持离线使用、原生文件对话框、自动更新、更好的性能 (原生子进程)。

Q: 如何更新桌面版？
A: 桌面版启动时自动检查更新，有新版本会提示下载安装。

· when green flag clicked → on "flag_clicked":
· broadcast (message) → broadcast "message"
· broadcast (message) and wait → broadcast "message" and wait
· when I receive (message) → on "message":

2.3 控制类

· wait (seconds) seconds → await this.wait(seconds)
· repeat (count) → repeat count:
· forever → forever:
· if (condition) then → if condition:

3. 命名转换规则

design/extensions/01-extension-api.md

01 - 扩展 API 参考

1. 概述

Sailfish Studio 扩展 API 允许开发者创建新的积木，扩展 SF 语言的功能。扩展可用 JavaScript、Rust 或 C++ 编写。

2. JavaScript API

```js
class MyExtension {
  static get info() {
    return {
      id: 'my-extension',
      name: 'My Extension',
      version: '1.0.0',
      description: 'My custom blocks'
    };
  }

  static getBlocks() {
    return [
      {
        opcode: 'myBlock',
        blockType: 'command',
        text: 'do something with [PARAM]',
        arguments: {
          PARAM: { type: 'string', defaultValue: 'hello' }
        }
      }
    ];
  }

  static execute(opcode, args, runtime) {
    if (opcode === 'myBlock') {
      console.log(args.PARAM);
    }
  }
}

Scratch.extensions.register(new MyExtension());
```

3. Rust API

Rust 扩展实现 SfExtension trait，编译为 Wasm 模块：

```rust
struct MyExtension;
impl SfExtension for MyExtension {
    fn info(&self) -> ExtensionInfo { ... }
    fn blocks(&self) -> Vec<BlockDefinition> { ... }
    fn execute(&self, opcode: &str, args: &[Value], state: &mut RuntimeState) -> Option<Value> { ... }
}
```

4. C/C++ API

C/C++ 扩展通过 Emscripten 编译为 Wasm，导出 C ABI 函数，由 Rust 侧通过 extern "C" 调用。

design/extensions/02-extension-lifecycle.md

02 - 扩展生命周期

1. 生命周期阶段

1.1 注册 (Registration)

· 扩展在编辑器启动或用户安装时注册
· 注册时提供 extension.json 或通过 API 声明积木、设置项
· 注册后积木出现在工具箱中

1.2 加载 (Loading)

· 扩展代码在第一次使用时按需加载（懒加载）
· 加载时分配沙箱环境 (Web Worker 或独立进程)
· 加载超时: 10 秒，超时后提示用户并禁用该扩展

1.3 执行 (Execution)

· 积木触发时调用扩展的 execute 方法
· 执行超时: 单次调用最长 5 秒，超时后终止并报错
· 扩展可访问 RuntimeState 读写变量、列表、广播消息

1.4 暂停 (Suspension)

· 项目停止运行时，扩展进入暂停状态
· 暂停时扩展不应执行任何后台操作
· 恢复执行时通过 on_resume 回调通知扩展

1.5 卸载 (Unloading)

· 用户禁用或卸载扩展时触发
· 扩展应清理资源 (定时器、网络连接、事件监听)
· 扩展进程被终止，所有内存释放

2. 状态图

```
[已安装] → (加载) → [已加载] → (执行) → [运行中]
                 ↓                    ↓
             [错误/超时]          [暂停/停止]
```

design/extensions/04-sandbox-model.md

04 - 沙箱模型

1. 概述

扩展和插件在沙箱环境中运行，限制其对系统资源的访问权限。沙箱分为 Web 端和桌面端两个实现。

2. 权限模型

扩展必须在 extension.json 或 plugin.json 中声明所需权限，用户安装时确认。

2.1 权限列表

· network: 允许发起 HTTP/WebSocket 请求（目标域名白名单在扩展描述中声明）
· storage: 允许读写本地存储 (IndexedDB/LocalStorage)
· filesystem: 允许读写本地文件系统 (仅桌面端，且限定在项目目录和用户数据目录)
· audio: 允许播放音频
· video: 允许播放视频
· dom: 允许访问 DOM (仅插件，且仅限编辑器 UI 区域)
· vm: 允许访问 sf-vm 内部状态 (仅高级扩展，需额外审核)

3. 沙箱实现

· Web 端: 扩展运行在独立 Web Worker 中，无 DOM 访问权限。网络请求通过 fetch 代理，由主线程控制。权限检查在主线程侧进行，Worker 侧无法绕过。
· 桌面端: 扩展运行在独立子进程中，通过 IPC 通信。文件系统访问通过虚拟文件系统 (VFS) 代理，限制在声明的目录范围内。进程级隔离确保扩展崩溃不影响编辑器。

design/collaboration/04-conflict-resolution.md

04 - 冲突解决算法

1. 概述

多人同时编辑时，冲突解决算法确保数据一致性。Sailfish Studio 针对不同数据类型采用不同的解决策略。

2. 积木树: OT 算法

积木树的操作 (插入、删除、移动、修改参数) 通过 OT 变换函数保证并发操作可交换。

2.1 变换规则

· 两个 block_insert 在不同位置 → 都生效
· 两个 block_insert 在相同位置 → 后到达的偏移 +1
· block_insert + block_delete (不同积木) → 都生效
· block_delete + block_update_field (同一积木) → block_update_field 被丢弃 (积木已删除)
· 两个 block_move (同一积木) → 最后到达的生效

3. 变量: LWW + 操作变换

· 变量修改采用 Last-Writer-Wins (LWW)，以服务器时间戳为准
· 如果两个用户在离线期间修改了同一变量，恢复连接后以最后修改为准
· 增量修改 (change variable by N) 转换为绝对值后应用 LWW

4. 造型编辑: 锁定机制

· 同一时间只能有一个用户编辑造型，进入造型编辑器时锁定
· 锁定期间其他用户看到只读视图和锁定提示
· 用户离开造型编辑器时自动解锁
· 锁定超时: 5 分钟无操作自动解锁（防止用户忘记关闭而长期锁定）

5. 角色属性: LWW

· 角色位置、大小、方向等属性使用 LWW
· 两个用户同时移动同一角色，最后一次操作生效

design/collaboration/05-offline-sync.md

05 - 离线同步设计

1. 概述

用户在离线状态下可以继续编辑项目，恢复连接后自动同步。

2. 离线操作记录

· 离线期间的所有操作记录在本地 IndexedDB 操作日志中
· 操作日志格式: 时间戳 + 操作类型 + 操作数据 (JSON)
· 日志保留 OFFLINE_LOG_MAX_HOURS 小时，超出后若仍离线则清除

3. 恢复连接同步流程

1. 检测网络恢复 → 连接协作服务器
2. 发送本地操作日志 (批量，按时间戳排序)
3. 服务器应用操作，检测冲突
4. 若无冲突 → 同步完成
5. 若有冲突 → 服务器返回冲突列表，客户端展示冲突解决对话框（展示本地版本和远程版本，用户逐项选择保留哪个）
6. 用户手动解决冲突后，服务器广播最终状态

4. 冲突解决 UI

· 冲突解决对话框分左右两栏：左侧显示本地版本（带 "本地" 标签），右侧显示远程版本（带 "远程" 标签）
· 差异部分高亮（背景色 --color-warning-light，即 #FEF3C7）
· 用户可以选择保留本地、保留远程、或手动合并
· 支持 "全部保留本地" 和 "全部保留远程" 批量操作

5. 同步状态指示器

· 状态栏右侧显示同步状态:
  · 已同步: 绿色圆点 + "已同步"
  · 同步中: 蓝色旋转图标 + "同步中..."
  · 离线: 灰色圆点 + "离线 (上次同步: HH:MM)"
  · 冲突待解决: 橙色圆点 + "有冲突待解决"

design/security/01-threat-model.md

01 - 威胁模型

1. 概述

Sailfish Studio 的威胁模型定义潜在攻击者、攻击向量和防护措施。

2. 信任边界

· 编辑器内部: 核心代码可信
· 扩展进程: 不可信 (来自第三方)
· 网络: 不可信 (数据传输)
· 本地文件系统: 部分可信 (用户文件)

3. 威胁清单

3.1 扩展威胁

· 恶意扩展窃取用户数据: 扩展声明 storage 权限后读取其他扩展的数据。防护: 存储隔离，每个扩展有独立的存储命名空间。
· 扩展注入 XSS: 扩展返回未转义的用户内容。防护: 扩展 API 自动转义输出，审核时静态扫描。
· 扩展耗尽资源: 无限循环、大量内存分配。防护: 执行超时 (5 秒)、内存限制 (128MB/扩展进程)、CPU 使用率监控。
· 扩展访问未授权网络: 扩展声明 network 权限但访问未声明域名。防护: 网络请求白名单检查在渲染进程侧强制实施。

3.2 协作威胁

· 未授权加入协作: 通过猜测链接加入。防护: 分享链接支持密码保护、有效期限制。
· 权限提升: 普通编辑者尝试执行所有者操作。防护: 服务器端权限校验，每次操作前检查权限。
· 消息篡改: 中间人攻击修改协作消息。防护: WebSocket 使用 WSS (TLS 加密)，消息带 HMAC 签名。

3.3 文件系统威胁

· 路径遍历: 扩展通过 ../ 访问项目目录外的文件。防护: 文件系统 VFS 做路径规范化，拒绝 .. 超出允许范围的请求。
· 恶意 .sf 文件: 打开包含恶意数据的 .sf 文件导致缓冲区溢出。防护: 所有输入验证，SQLite 查询使用参数化，资源 BLOB 大小限制 (100MB/文件)。

design/security/02-sandbox-boundaries.md

02 - 沙箱边界

1. 概述

Sailfish Studio 的沙箱边界定义扩展/插件与系统资源的隔离方式。

2. 边界定义

2.1 DOM 隔离

· 扩展无权访问 DOM，所有 UI 操作通过 API 代理。尝试直接访问 document 或 window 时返回 undefined。
· 插件可访问编辑器 UI 的指定区域 (sf-editor 的 <div id="plugin-panel">)，但不能访问其他区域 (菜单、工具栏、舞台)。

2.2 存储隔离

· 每个扩展拥有独立的 IndexedDB/LocalStorage 命名空间，键名自动添加扩展 ID 前缀
· 跨扩展数据共享必须通过 sailfish.storage.share(key, value, targetExtensionId) API

2.3 网络隔离

· 扩展的网络请求通过编辑器主线程的代理执行，不在扩展进程中直接发起
· 代理检查请求 URL 是否在扩展声明的域名白名单中，拒绝非白名单请求
· 请求速率限制: 60 次/分钟，超出后返回 429

2.4 进程隔离 (桌面端)

· 每个扩展在独立子进程中运行，通过 IPC 通信。扩展进程崩溃不影响编辑器和其他扩展。
· 子进程使用操作系统级沙箱 (macOS App Sandbox、Windows Job Objects)，限制文件系统和网络访问。
· 扩展进程内存限制 128MB，超出时进程被终止并提示用户。

design/security/03-permission-model.md

03 - 权限模型

1. 概述

扩展和插件必须声明所需权限，用户安装时确认。权限不可在运行时动态请求。

2. 权限声明 (extension.json / plugin.json)

· storage: 本地存储读写

· audio: 音频播放和控制
· video: 视频播放和控制
· dom: DOM 访问 (仅插件，限制在指定 UI 区域)
· vm: sf-vm 内部状态访问 (需额外审核，仅限官方认证扩展)

4. 权限确认 UI

· 安装扩展/插件时弹出权限确认对话框，列出所有权限及说明
· 用户必须逐项勾选同意，不能批量同意
· 权限不可在运行时动态请求

design/security/04-csp-policy.md

04 - CSP 策略

1. 概述

Content Security Policy (CSP) 限制浏览器中可执行的脚本和可加载的资源。

2. Web 端 CSP 头

```
Content-Security-Policy:
  default-src 'self';
  script-src 'self' 'wasm-unsafe-eval';
  style-src 'self' 'unsafe-inline';
  img-src 'self' data: blob:;
  connect-src 'self' https://api.sailfish.studio wss://collab.sailfish.studio;
  worker-src 'self' blob:;
  font-src 'self';
```

3. 沙箱 iframe (社区渠道扩展)

```
Content-Security-Policy:
  default-src 'none';
  script-src 'self';
  connect-src 'none';
```

4. 桌面端

· 桌面端不使用 CSP 头，但通过操作系统级沙箱实现等效限制

05 - 代码签名

02 - 性能基准

1. 概述

定义 Sailfish Studio 必须满足的性能基准。

· 1000 积木项目编译时间 < 200ms

· 项目打开时间 (1000 积木) < 1 秒

5. 协作基准

· 操作延迟 < 200ms (正常网络)
· 32 人同时编辑帧率影响 < 5fps

· Rust: criterion + cargo bench

04 - 模糊测试策略

1. 概述

对核心模块进行模糊测试，发现边界情况和安全漏洞。

2. 测试目标

· 项目加载器 (sf-parser): 随机字节输入，验证不会 panic，错误处理正确
· 编译器 (sf-vm-compiler): 随机 AST 输入，验证生成的 JS 代码合法
· 协作协议 (collaboration): 随机操作序列，验证 OT 变换结果一致

3. 工具

· Rust: cargo-fuzz (libFuzzer)
· 持续运行时间: 每次 PR ≥ 1 小时，发布前 ≥ 24 小时

4. CI 集成

· 每次 push 到 main 时运行模糊测试 1 小时
· 发布候选版本时运行模糊测试 24 小时，无崩溃方可发布
· 发现崩溃时自动生成最小复现用例并归档
