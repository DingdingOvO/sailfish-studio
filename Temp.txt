design/ui/07-components/dropdown.md

下拉菜单组件规范

1. 用途

用于菜单栏、右键菜单、选择器、工具栏溢出菜单。

2. 尺寸

· 菜单项高度: 32px
· 菜单项最小宽度: 160px，最大宽度: 320px
· 图标区域: 24px × 24px，位于文本左侧
· 快捷键文本: 右对齐，--text-sm，颜色 --text-secondary
· 分隔线: 1px --border-color，上下内边距 --space-1

3. 嵌套菜单

· 子菜单从父菜单项右侧弹出，弹出前有 100ms 延迟（防止快速划过时意外展开）
· 子菜单与父菜单间距 4px
· 嵌套深度最多 3 层，超出时考虑重新组织菜单结构

4. 交互

· ↑↓ 键移动焦点，Enter 触发菜单项，Esc 关闭
· 支持搜索过滤（顶部输入框，按需出现，当菜单项超过 15 个时自动显示搜索框）
· 菜单项禁用时灰色显示，仍可聚焦但不响应 Enter
· 关闭菜单后焦点回到触发元素

design/language/01-lexical-grammar.md

01 - SF 语言词法规则

1. 概述

SF 语言 (.sfl) 的词法规则定义代码的最小组成单元。

2. Token 类型

2.1 关键字

```
var, let, const, func, return, void,
if, else, elif, repeat, forever, while,
broadcast, and, wait, on,
struct, enum, type, import, export
```

2.2 标识符

· 规则: [a-zA-Z_][a-zA-Z0-9_]*
· 变量名、函数名、类型名均使用标识符
· 区分大小写

2.3 字面量

· 数字: [0-9]+(\.[0-9]+)?（整数和浮点数统一解析）
· 字符串: "..." 双引号包裹，支持 \n、\t、\"、\\ 转义
· 布尔: true、false
· 空值: null

2.4 运算符

· 算术: +, -, *, /, %
· 比较: ==, !=, >, <, >=, <=
· 逻辑: and, or, not
· 赋值: =, +=, -=, *=, /=
· 成员访问: .
· 箭头: ->

2.5 注释

· 单行: # 到行末
· 多行: ### 开始，### 结束（可嵌套）

design/language/04-block-mapping.md

04 - 积木 ↔ .sfl 映射规则

1. 概述

定义 Scratch 积木与 .sfl 语法之间的双向转换规则，确保积木编辑器中的任何操作都能无损转换为 .sfl 代码，反之亦然。

2. 转换规则表

2.1 运动类

· move (steps) steps → this.moveSteps(steps)
· turn right (degrees) degrees → this.turnRight(degrees)
· turn left (degrees) degrees → this.turnLeft(degrees)
· go to x: (x) y: (y) → this.goToXY(x, y)
· glide (secs) secs to x: (x) y: (y) → this.glide(secs, x, y)

2.2 事件类

· when green flag clicked → on "flag_clicked":
· broadcast (message) → broadcast "message"
· broadcast (message) and wait → broadcast "message" and wait
· when I receive (message) → on "message":

2.3 控制类

· wait (seconds) seconds → await this.wait(seconds)
· repeat (count) → repeat count:
· forever → forever:
· if (condition) then → if condition:
· if (condition) then ... else → if condition: ... else:
· wait until (condition) → while not condition:

2.4 变量类

· set [var] to (value) → var = value
· change [var] by (delta) → var += delta
· show variable [var] → this.showVariable("var")
· hide variable [var] → this.hideVariable("var")

2.5 列表类

· add (item) to [list] → list.push(item)
· delete (index) of [list] → list.deleteAt(index)
· insert (item) at (index) of [list] → list.insertAt(index, item)
· item (index) of [list] → list[index]

2.6 自定义积木

· define (name) (params...) → func name(params...):
· (name) (args...) → name(args...)

3. 命名转换规则

· 积木中文标签 → 英文标识符（通过积木 ID 映射，保证跨语言一致）
· 变量名保留原始名称，空格转为下划线
· 列表名保留原始名称，后缀 _list
· 广播消息名保留原始名称，空格转为下划线

design/extensions/01-extension-api.md

01 - 扩展 API 参考

1. 概述

Sailfish Studio 扩展 API 允许开发者创建新的积木，扩展 SF 语言的功能。扩展可用 JavaScript、Rust 或 C++ 编写。

2. JavaScript API

```js
class MyExtension {
  static get info() {
    return {
      id: 'my-extension',
      name: 'My Extension',
      version: '1.0.0',
      description: 'My custom blocks'
    };
  }

  static getBlocks() {
    return [
      {
        opcode: 'myBlock',
        blockType: 'command',
        text: 'do something with [PARAM]',
        arguments: {
          PARAM: { type: 'string', defaultValue: 'hello' }
        }
      }
    ];
  }

  static execute(opcode, args, runtime) {
    if (opcode === 'myBlock') {
      console.log(args.PARAM);
    }
  }
}

Scratch.extensions.register(new MyExtension());
```

3. Rust API

Rust 扩展实现 SfExtension trait，编译为 Wasm 模块：

```rust
struct MyExtension;
impl SfExtension for MyExtension {
    fn info(&self) -> ExtensionInfo { ... }
    fn blocks(&self) -> Vec<BlockDefinition> { ... }
    fn execute(&self, opcode: &str, args: &[Value], state: &mut RuntimeState) -> Option<Value> { ... }
}
```

4. C/C++ API

C/C++ 扩展通过 Emscripten 编译为 Wasm，导出 C ABI 函数，由 Rust 侧通过 extern "C" 调用。

design/extensions/02-extension-lifecycle.md

02 - 扩展生命周期

1. 生命周期阶段

1.1 注册 (Registration)

· 扩展在编辑器启动或用户安装时注册
· 注册时提供 extension.json 或通过 API 声明积木、设置项
· 注册后积木出现在工具箱中

1.2 加载 (Loading)

· 扩展代码在第一次使用时按需加载（懒加载）
· 加载时分配沙箱环境 (Web Worker 或独立进程)
· 加载超时: 10 秒，超时后提示用户并禁用该扩展

1.3 执行 (Execution)

· 积木触发时调用扩展的 execute 方法
· 执行超时: 单次调用最长 5 秒，超时后终止并报错
· 扩展可访问 RuntimeState 读写变量、列表、广播消息

1.4 暂停 (Suspension)

· 项目停止运行时，扩展进入暂停状态
· 暂停时扩展不应执行任何后台操作
· 恢复执行时通过 on_resume 回调通知扩展

1.5 卸载 (Unloading)

· 用户禁用或卸载扩展时触发
· 扩展应清理资源 (定时器、网络连接、事件监听)
· 扩展进程被终止，所有内存释放

2. 状态图

```
[已安装] → (加载) → [已加载] → (执行) → [运行中]
                 ↓                    ↓
             [错误/超时]          [暂停/停止]
```

design/extensions/03-plugin-api.md

03 - 插件 API 参考

1. 概述

插件 API 允许开发者扩展编辑器的功能（不增加新积木），修改 UI、主题、快捷键等。插件需通过审核才能进入官方市场。

2. 插件能力

2.1 UI 扩展

· 添加自定义面板: sailfish.ui.registerPanel(panelConfig)
· 修改工具栏: sailfish.ui.addToolbarButton(buttonConfig)
· 注册右键菜单: sailfish.ui.registerContextMenu(menuConfig)

2.2 主题扩展

· 注册新主题: sailfish.theme.register(themeConfig)
· 主题可覆盖颜色、字体、圆角、阴影

2.3 快捷键

· 注册快捷键: sailfish.shortcuts.register(command, keybinding, callback)
· 快捷键冲突时提示用户手动解决

2.4 编辑器钩子

· 项目打开/关闭: onProjectOpen(callback), onProjectClose(callback)
· 保存前/后: onBeforeSave(callback), onAfterSave(callback)
· 编译前/后: onBeforeCompile(callback), onAfterCompile(callback)

3. 插件描述文件

```json
{
  "id": "my-plugin",
  "version": "1.0.0",
  "name": "My Plugin",
  "description": "Custom editor plugin",
  "author": "username",
  "permissions": ["ui", "theme", "shortcuts"],
  "entry": "./index.js"
}
```

design/extensions/04-sandbox-model.md

04 - 沙箱模型

1. 概述

扩展和插件在沙箱环境中运行，限制其对系统资源的访问权限。沙箱分为 Web 端和桌面端两个实现。

2. 权限模型

扩展必须在 extension.json 或 plugin.json 中声明所需权限，用户安装时确认。

2.1 权限列表

· network: 允许发起 HTTP/WebSocket 请求（目标域名白名单在扩展描述中声明）
· storage: 允许读写本地存储 (IndexedDB/LocalStorage)
· filesystem: 允许读写本地文件系统 (仅桌面端，且限定在项目目录和用户数据目录)
· audio: 允许播放音频
· video: 允许播放视频
· dom: 允许访问 DOM (仅插件，且仅限编辑器 UI 区域)
· vm: 允许访问 sf-vm 内部状态 (仅高级扩展，需额外审核)

3. 沙箱实现

· Web 端: 扩展运行在独立 Web Worker 中，无 DOM 访问权限。网络请求通过 fetch 代理，由主线程控制。权限检查在主线程侧进行，Worker 侧无法绕过。
· 桌面端: 扩展运行在独立子进程中，通过 IPC 通信。文件系统访问通过虚拟文件系统 (VFS) 代理，限制在声明的目录范围内。进程级隔离确保扩展崩溃不影响编辑器。

03 - 用户存在感设计

design/collaboration/04-conflict-resolution.md

04 - 冲突解决算法

1. 概述

多人同时编辑时，冲突解决算法确保数据一致性。Sailfish Studio 针对不同数据类型采用不同的解决策略。

2. 积木树: OT 算法

积木树的操作 (插入、删除、移动、修改参数) 通过 OT 变换函数保证并发操作可交换。

2.1 变换规则

· 两个 block_insert 在不同位置 → 都生效
· 两个 block_insert 在相同位置 → 后到达的偏移 +1
· block_insert + block_delete (不同积木) → 都生效
· block_delete + block_update_field (同一积木) → block_update_field 被丢弃 (积木已删除)
· 两个 block_move (同一积木) → 最后到达的生效

3. 变量: LWW + 操作变换

· 变量修改采用 Last-Writer-Wins (LWW)，以服务器时间戳为准
· 如果两个用户在离线期间修改了同一变量，恢复连接后以最后修改为准
· 增量修改 (change variable by N) 转换为绝对值后应用 LWW

4. 造型编辑: 锁定机制

· 同一时间只能有一个用户编辑造型，进入造型编辑器时锁定
· 锁定期间其他用户看到只读视图和锁定提示
· 用户离开造型编辑器时自动解锁
· 锁定超时: 5 分钟无操作自动解锁（防止用户忘记关闭而长期锁定）

5. 角色属性: LWW

· 角色位置、大小、方向等属性使用 LWW
· 两个用户同时移动同一角色，最后一次操作生效

design/collaboration/05-offline-sync.md

05 - 离线同步设计

1. 概述

用户在离线状态下可以继续编辑项目，恢复连接后自动同步。

2. 离线操作记录

· 离线期间的所有操作记录在本地 IndexedDB 操作日志中
· 操作日志格式: 时间戳 + 操作类型 + 操作数据 (JSON)
· 日志保留 OFFLINE_LOG_MAX_HOURS 小时，超出后若仍离线则清除

3. 恢复连接同步流程

1. 检测网络恢复 → 连接协作服务器
2. 发送本地操作日志 (批量，按时间戳排序)
3. 服务器应用操作，检测冲突
4. 若无冲突 → 同步完成
5. 若有冲突 → 服务器返回冲突列表，客户端展示冲突解决对话框（展示本地版本和远程版本，用户逐项选择保留哪个）
6. 用户手动解决冲突后，服务器广播最终状态

4. 冲突解决 UI

· 冲突解决对话框分左右两栏：左侧显示本地版本（带 "本地" 标签），右侧显示远程版本（带 "远程" 标签）
· 差异部分高亮（背景色 --color-warning-light，即 #FEF3C7）
· 用户可以选择保留本地、保留远程、或手动合并
· 支持 "全部保留本地" 和 "全部保留远程" 批量操作

5. 同步状态指示器

· 状态栏右侧显示同步状态:
  · 已同步: 绿色圆点 + "已同步"
  · 同步中: 蓝色旋转图标 + "同步中..."
  · 离线: 灰色圆点 + "离线 (上次同步: HH:MM)"
  · 冲突待解决: 橙色圆点 + "有冲突待解决"

design/security/01-threat-model.md

01 - 威胁模型

1. 概述

Sailfish Studio 的威胁模型定义潜在攻击者、攻击向量和防护措施。

2. 信任边界

· 编辑器内部: 核心代码可信
· 扩展进程: 不可信 (来自第三方)
· 网络: 不可信 (数据传输)
· 本地文件系统: 部分可信 (用户文件)

3. 威胁清单

3.1 扩展威胁

· 恶意扩展窃取用户数据: 扩展声明 storage 权限后读取其他扩展的数据。防护: 存储隔离，每个扩展有独立的存储命名空间。
· 扩展注入 XSS: 扩展返回未转义的用户内容。防护: 扩展 API 自动转义输出，审核时静态扫描。
· 扩展耗尽资源: 无限循环、大量内存分配。防护: 执行超时 (5 秒)、内存限制 (128MB/扩展进程)、CPU 使用率监控。
· 扩展访问未授权网络: 扩展声明 network 权限但访问未声明域名。防护: 网络请求白名单检查在渲染进程侧强制实施。

3.2 协作威胁

· 未授权加入协作: 通过猜测链接加入。防护: 分享链接支持密码保护、有效期限制。
· 权限提升: 普通编辑者尝试执行所有者操作。防护: 服务器端权限校验，每次操作前检查权限。
· 消息篡改: 中间人攻击修改协作消息。防护: WebSocket 使用 WSS (TLS 加密)，消息带 HMAC 签名。

3.3 文件系统威胁

· 路径遍历: 扩展通过 ../ 访问项目目录外的文件。防护: 文件系统 VFS 做路径规范化，拒绝 .. 超出允许范围的请求。
· 恶意 .sf 文件: 打开包含恶意数据的 .sf 文件导致缓冲区溢出。防护: 所有输入验证，SQLite 查询使用参数化，资源 BLOB 大小限制 (100MB/文件)。

design/security/02-sandbox-boundaries.md

02 - 沙箱边界

1. 概述

Sailfish Studio 的沙箱边界定义扩展/插件与系统资源的隔离方式。

2. 边界定义

2.1 DOM 隔离

· 扩展无权访问 DOM，所有 UI 操作通过 API 代理。尝试直接访问 document 或 window 时返回 undefined。
· 插件可访问编辑器 UI 的指定区域 (sf-editor 的 <div id="plugin-panel">)，但不能访问其他区域 (菜单、工具栏、舞台)。

2.2 存储隔离

· 每个扩展拥有独立的 IndexedDB/LocalStorage 命名空间，键名自动添加扩展 ID 前缀
· 跨扩展数据共享必须通过 sailfish.storage.share(key, value, targetExtensionId) API

2.3 网络隔离

· 扩展的网络请求通过编辑器主线程的代理执行，不在扩展进程中直接发起
· 代理检查请求 URL 是否在扩展声明的域名白名单中，拒绝非白名单请求
· 请求速率限制: 60 次/分钟，超出后返回 429

2.4 进程隔离 (桌面端)

· 每个扩展在独立子进程中运行，通过 IPC 通信。扩展进程崩溃不影响编辑器和其他扩展。
· 子进程使用操作系统级沙箱 (macOS App Sandbox、Windows Job Objects)，限制文件系统和网络访问。
· 扩展进程内存限制 128MB，超出时进程被终止并提示用户。

design/security/03-permission-model.md

03 - 权限模型

1. 概述

扩展和插件必须声明所需权限，用户安装时确认。权限不可在运行时动态请求。

2. 权限声明 (extension.json / plugin.json)

```json
{
  "permissions": [
    "network:api.example.com",
    "storage",
    "audio"
  ]
}
```

3. 权限列表

· network / network:<domain>: 网络请求，可限制域名
· storage: 本地存储读写
· filesystem: 文件系统访问 (仅桌面端，限制在项目目录和用户数据目录)
· audio: 音频播放和控制
· video: 视频播放和控制
· dom: DOM 访问 (仅插件，限制在指定 UI 区域)
· vm: sf-vm 内部状态访问 (需额外审核，仅限官方认证扩展)

4. 权限确认 UI

· 安装扩展/插件时弹出权限确认对话框，列出所有权限及说明
· 用户必须逐项勾选同意，不能批量同意
· 权限不可在运行时动态请求

design/security/04-csp-policy.md

04 - CSP 策略

1. 概述

Content Security Policy (CSP) 限制浏览器中可执行的脚本和可加载的资源。

2. Web 端 CSP 头

```
Content-Security-Policy:
  default-src 'self';
  script-src 'self' 'wasm-unsafe-eval';
  style-src 'self' 'unsafe-inline';
  img-src 'self' data: blob:;
  connect-src 'self' https://api.sailfish.studio wss://collab.sailfish.studio;
  worker-src 'self' blob:;
  font-src 'self';
```

3. 沙箱 iframe (社区渠道扩展)

```
Content-Security-Policy:
  default-src 'none';
  script-src 'self';
  connect-src 'none';
```

4. 桌面端

· 桌面端不使用 CSP 头，但通过操作系统级沙箱实现等效限制

design/security/05-code-signing.md

05 - 代码签名

1. 概述

代码签名确保扩展、插件和桌面应用的来源可验证，未被篡改。

2. 扩展/插件签名

· 提交到官方市场的扩展/插件由 Sailfish Studio 官方签名
· 签名密钥存储在 CI/CD Secrets 中，仅构建流程可访问
· 编辑器加载扩展时验证签名，签名无效或缺失时拒绝加载

3. 桌面应用签名

· macOS: Developer ID 证书 + 公证
· Windows: EV Code Signing Certificate
· Linux: GPG 签名

4. 构建来源证明 (SLSA Level 2+)

· GitHub Actions 生成构建来源证明 (actions/attest-build-provenance)
· 用户可验证发布包是否由官方 CI 构建，未被篡改
· 构建配置和依赖锁定文件在 Git 中可审计

design/testing/02-performance-bench.md

02 - 性能基准

1. 概述

定义 Sailfish Studio 必须满足的性能基准。

2. 编译器基准

· 1000 积木项目编译时间 < 200ms
· 增量编译 (修改 1 个积木) < 20ms
· 测试项目: 标准测试集 bench/1000-blocks.sf

3. 渲染器基准

· 1000 个角色同时移动: ≥ 60fps
· 10000 个克隆体: ≥ 30fps
· 舞台缩放 (25% → 400%): 缩放过程中 ≥ 55fps
· 测试设备: 中等配置 (Intel i5 / 8GB RAM / 集成显卡)

4. 编辑器基准

· 积木拖拽帧率波动 ≤ 3fps
· 工具箱搜索过滤延迟 < 100ms
· 项目打开时间 (1000 积木) < 1 秒

5. 协作基准

· 操作延迟 < 200ms (正常网络)
· 32 人同时编辑帧率影响 < 5fps

6. 测试工具

· Rust: criterion + cargo bench
· Web: Lighthouse CI + Playwright 性能录制

design/testing/04-fuzzing-strategy.md

04 - 模糊测试策略

1. 概述

对核心模块进行模糊测试，发现边界情况和安全漏洞。

2. 测试目标

· 项目加载器 (sf-parser): 随机字节输入，验证不会 panic，错误处理正确
· 编译器 (sf-vm-compiler): 随机 AST 输入，验证生成的 JS 代码合法
· 协作协议 (collaboration): 随机操作序列，验证 OT 变换结果一致

3. 工具

· Rust: cargo-fuzz (libFuzzer)
· 持续运行时间: 每次 PR ≥ 1 小时，发布前 ≥ 24 小时

4. CI 集成

· 每次 push 到 main 时运行模糊测试 1 小时
· 发布候选版本时运行模糊测试 24 小时，无崩溃方可发布
· 发现崩溃时自动生成最小复现用例并归档
