```markdown
# 01 - 项目概述

[返回 README](./README.md) | [下一章：核心概念](./02-concepts.md)

## 1.1 定位

Sailfish Studio 是一个面向专业创作者的图形化编程与全栈开发平台。创作者用它做四件事：

- **创作游戏和应用**：用积木拖拽编程，发布到 Web、桌面、移动端。
- **开发服务器后端**：用 .sfl 纯文本语言写后端逻辑，通过 SF Runtime 部署。
- **实时协作**：多人同时编辑同一个项目，像 Figma 一样。
- **编译为原生程序**：将项目 AOT 编译为独立可执行文件，无运行时依赖。

## 1.2 核心目标

- **极致性能**：核心引擎 Rust 重写，编译为 WebAssembly。桌面端基于 Tauri。支持 AOT 编译。
- **绝对稳定**：舞台和编辑器帧率波动在任何负载下 ≤ `FPS_FLUCTUATION_MAX` fps。重负载下不低于 `FPS_MIN_ACCEPTABLE` fps。多进程隔离确保一个项目崩溃不影响其他项目。
- **专业品质**：严谨的类型系统对标 Rust，自研 UI 框架，自研纯文本语言 `.sfl`。
- **原生协作**：内置多人实时协作，支持用户系统和链接分享。
- **开放生态**：兼容 TurboWarp JS 扩展，支持 Rust/C++ 扩展，社区可贡献。

## 1.3 Sailfish Studio 不做的事

以下功能**明确不在需求范围内**：

- **不做社交网络**：不内置动态流、关注系统、点赞、排行榜。
- **不做模板市场**：不内置收费模板商店。
- **不做 AI 生成内容审核**：AI 生成的 .sfl 代码由用户自行负责。
- **不做内置直播推流**：舞台画面可以导出，但不内置推流功能。
- **不做移动端手机 UI**：移动端仅适配平板。
- **不做内置数据库服务**：云变量提供简单的键值共享。
- **不做支付系统**：不内置任何支付、订阅、打赏功能。

## 1.4 与上游的关系
从 TurboWarp 分叉全部 44 个仓库，核心模块 Rust 重写，仅保留 JS 扩展兼容。
```

```markdown
# 02 - 核心概念

[上一章](./01-overview.md) | [下一章：技术架构](./03-architecture.md)

## 2.1 积木
主要的编程方式，操作与 Scratch 相同。底层引擎 Rust 自研，不依赖 Blockly。内置全部 Scratch 3.0 积木及 TurboWarp 增强。扩展可增加新积木。

## 2.2 .sfl 纯文本语言
从积木分叉出的纯文本形态。语法与积木一一对应。文件后缀 `.sfl`。可被 SF Runtime 执行，也可 AOT 编译。提供 VS Code 扩展。

## 2.3 .sf 项目文件
项目保存格式，SQLite 数据库。比 ZIP 紧凑，支持增量写入和实时保存。包含：元信息、校验码、积木树、资源 BLOB、项目设置、扩展列表与设置。

## 2.4 SF 程序包
.sfl 文件和资源打包的可执行单元，后缀 `.sfp`。非加密，可混淆保护。

## 2.5 SF Runtime
命令行工具，执行 .sfl 和 .sfp。核心命令：`sf run`、`sf pack`、`sf new`、`sf check`。有头/无头两种模式。

## 2.6 AOT 编译
将项目编译为原生可执行文件，不含解释器。支持 XML 配置或命令行参数。

## 2.7 扩展
增强语言能力的模块。兼容 TurboWarp JS 扩展，支持 Rust/C++/TS。官方市场 + 社区渠道。

## 2.8 编辑器插件
增强编辑器功能的模块，不增加积木。
```

```markdown
# 03 - 技术架构

[上一章](./02-concepts.md) | [下一章：积木编辑器](./04-editor.md)

## 3.1 全栈技术栈
- 核心语言：Rust 1.95+，编译为 wasm32-unknown-unknown
- 前端构建：Next.js 16.2 (Turbopack)
- 桌面端：Tauri 2.0
- 包管理：pnpm 10+
- 数据库：SQLite
- C/C++ 扩展：Emscripten 4.2
- AOT 后端：LLVM 18+

## 3.2 多进程架构

Sailfish Studio 采用三进程架构确保稳定性。

| 进程 | 职责 | 生命周期 | 数量 |
|------|------|---------|------|
| 主进程 | 窗口管理、菜单、系统托盘、自动更新、IPC 中枢 | 启动到退出 | 1 |
| 渲染进程 | 编辑器 UI（积木区、舞台、面板） | 启动到退出 | 1（常驻） |
| 扩展进程 | 项目执行（VM、编译、扩展） | 按项目 | 每项目 1 个 |

**关键约束**：
- 渲染进程只负责 UI，不执行项目逻辑。
- 每个项目运行在独立扩展进程中，完全隔离。
- 打开新项目不重新加载渲染进程。
- 关闭项目则终止扩展进程，内存立即释放。

**浏览器端实现**：渲染进程 = 主线程，扩展进程 = Web Worker。  
**桌面端实现**：渲染进程 = WebView，扩展进程 = Tauri sidecar 子进程（推荐）或 Web Worker（降级）。

## 3.3 源代码质量要求
- Rust：`cargo fmt`、`cargo clippy -D warnings`、零 `unsafe`（除非审查批准）、禁止 `unwrap()` 在生产代码中、测试覆盖率 ≥ 95%。
- TS/JS：Biome 格式化和 lint、禁止 `any`（除非审查批准）、禁止魔法数字、测试覆盖率 ≥ 95%。
- 代码审查：所有 PR 必须审查通过，CI 必须全绿。

## 3.4 仓库组织（Monorepo，6 个主仓库）
- **sf-core** (28 包)：VM、编译器、运行时、积木引擎、渲染器、解析器、存储、音频、.sfl 语言、Runtime、AOT 编译器、混淆、调试、类型定义
- **sf-editor** (13 包)：UI 框架、编辑器主应用、多窗口管理、addons、插件引擎、插件市场、社区、平板 UI、调试控制台、本地化
- **sf-tools** (8 包)：打包器、解包器、CLI、sb3fix、脚手架、后处理
- **sf-services** (6 包)：云变量、账户、分享、统计、代理、轻量 API
- **sf-extensions** (21+ 扩展 + 市场)：扩展内容、市场网站、开发工具库
- **sf-docs**：文档站
```

```markdown
# 04 - 积木编辑器

[上一章](./03-architecture.md) | [下一章：多人协作](./05-collaboration.md)

## 4.1 编辑器基础
- 全新积木视觉，不模仿 Blockly。
- 拖拽吸附（`MAGNETIC_SNAP_DISTANCE_PX` px）。
- 动态模糊拖尾（`TRAIL_FRAME_COUNT` 帧，透明度 `TRAIL_MAX_ALPHA` → `TRAIL_MIN_ALPHA`）。
- 撤销/重做（`HISTORY_STACK_MAX_DEPTH` 条）。
- 右键菜单：复制、粘贴、删除、注释、折叠。
- 工具箱：内置积木和扩展积木统一显示。

## 4.2 类型系统
创建变量必须选类型，每种类型有专属图标和色差：

| 类型 | 说明 |
|------|------|
| `any` | 通用类型，默认，橙色系 |
| `string` | 纯字符串 |
| `number` | 双精度浮点 |
| `float` | 高精度浮点 |
| `long` | 大整数 |
| `bigint` | 无限大整数 |
| `bool` | 布尔值 |

公有/私有变量分组显示。导入外部项目时默认通用类型。

## 4.3 高级语言特性
泛型、可选类型、联合类型、类型别名、结构体、枚举、完整函数签名、模块与命名空间、错误处理、常量与不可变数据。

## 4.4 拖拽交互
- 拖出：积木→.sfl、角色→.sprite、背景→.backdrop、造型→图片、声音→音频、项目卡片→.sf、舞台→截图。
- 拖入：图片、音频、.sfl、.sb3/.sf、.sprite、.backdrop、扩展文件。
- 文件暂存区：编辑器关闭前非空则提示保存。
- 桌面端多窗口，Web 端标签页多开（不支持跨标签页拖拽）。
- 平板：拖出改为屏幕边缘菜单。

## 4.5 协作模式下的编辑器行为
- 其他用户编辑的积木显示其颜色边框。
- 同一积木被两人同时拖拽时，先开始的生效。
```

```markdown
# 05 - 多人实时协作

[上一章](./04-editor.md) | [下一章：UI 与设计语言](./06-ui.md)

## 5.1 协作模式
参考 Figma：实时同步、用户光标可见、不同颜色标记、积木编辑状态可见。支持跟随模式。支持评论与 @提及。

## 5.2 连接方式
- 用户系统邀请（输入用户名或邮箱）
- 分享链接（可设权限和有效期）
- 局域网发现（桌面端，直连低延迟）

## 5.3 权限模型

| 角色 | 编辑积木 | 修改角色 | 增删角色 | 导出 | 邀请 | 踢人 |
|------|---------|---------|---------|------|------|------|
| 所有者 | 是 | 是 | 是 | 是 | 是 | 是 |
| 编辑者 | 是 | 是 | 是 | 是 | 否 | 否 |
| 评论者 | 否 | 否 | 否 | 否 | 否 | 否 |
| 查看者 | 否 | 否 | 否 | 否 | 否 | 否 |

## 5.4 冲突解决
积木树采用 OT/CRDT。变量以最后写入为准。造型编辑期间锁定。角色属性最后写入生效。

## 5.5 离线编辑
离线操作记录在本地日志中，恢复连接后同步。同步状态指示器在状态栏显示。离线日志保留 `OFFLINE_LOG_MAX_HOURS` 小时。

## 5.6 用户系统
邮箱注册、OAuth 登录。用户资料、好友、团队。通知中心（站内和邮件可选）。

## 5.7 协作中的扩展行为
扩展必须被所有参与者安装。本地存储、文件操作等扩展不进行同步。

## 5.8 性能要求
- 协作延迟 < `COLLAB_LATENCY_MAX_MS` ms
- 协作不影响编辑器帧率
- 单房间最多 `COLLAB_MAX_PARTICIPANTS` 人
- 服务器单节点支持 1000 并发房间
```

```markdown
# 08 - 运行时与打包

[上一章](./07-extensions.md) | [下一章：跨平台](./09-platform.md)

## 8.1 SF Runtime
命令行工具。`sf run` 执行 .sfl 或 .sfp。有头模式（图形）和无头模式（服务器后端）。打包可选内嵌或依赖外部 Runtime。

## 8.2 AOT 编译
XML 配置或命令行参数。编译流程：解析→优化→LLVM 生成机器码→链接启动代码→输出原生可执行文件。

## 8.3 混淆
`sf-obfuscator` 保护商业代码。不可逆。
```

```markdown
# 10 - 调试与日志

[上一章](./09-platform.md) | [下一章：非功能性需求](./11-nfr.md)

## 10.1 日志分级
6 级：TRACE、DEBUG、INFO、WARN、ERROR、FATAL。正常模式仅记录 WARN 及以上。

## 10.2 多进程收集
渲染进程汇总所有扩展进程的日志。每条日志标注 `process_id`。

## 10.3 调试控制台
Ctrl+Shift+D 打开。过滤、搜索、导出日志。性能快照。调用栈查看。进程状态。

## 10.4 性能保障
正常模式 < 0.5 FPS 影响。调试模式 < 3 FPS。环形缓冲区，超出丢弃低优先级。
```

```markdown
# 11 - 非功能性需求

[上一章](./10-debug.md) | [下一章：路线图](./12-roadmap.md)

## 11.1 性能
- 1000 积木编译 < `COMPILE_TIME_TARGET_MS`
- 重负载帧率 ≥ `FPS_MIN_ACCEPTABLE` fps，波动 ≤ `FPS_FLUCTUATION_MAX` fps
- 编辑拖拽波动 ≤ 3 fps
- IPC 延迟：桌面 < 1ms，浏览器 < 2ms
- 空项目 Wasm 内存 < `WASM_HEAP_BUDGET_DEFAULT_MB / 4`
- 大型项目 Wasm 内存 < `WASM_HEAP_BUDGET_DEFAULT_MB`

## 11.2 安全
扩展审核、沙箱隔离、进程隔离、CSP、代码签名。

## 11.3 兼容性
Chrome 90+、Firefox 90+、Safari 15+。Windows 10+、macOS 11+、Linux。Android 10+。

## 11.4 可维护性
测试覆盖率 ≥ 95%。所有模块文档化。禁止魔法数字。

## 11.5 国际化
50 种语言。AI 翻译。日志始终英文。
```
