# 03 - 数据流与状态管理

[返回 README](../README.md)

## 1. 核心原则

- **单一数据源**: 项目状态 (积木树、变量、列表) 的权威数据源在扩展进程的 sf-vm 中。渲染进程不持有权威状态，仅持有 UI 状态 (选中项、滚动位置、面板展开/折叠)。
- **单向数据流**: 用户操作 → 渲染进程发送 RPC → 扩展进程执行 → 状态变更 → 推送回渲染进程 → UI 更新。
- **乐观更新**: 对于高频操作 (如拖拽积木)，渲染进程可先乐观更新 UI，再异步同步到扩展进程，若被拒绝则回滚。

## 2. 状态分类

### 2.1 权威状态 (Source of Truth)

- **存储位置**: 扩展进程 sf-vm 内存 (Wasm 线性内存)
- **内容**: 积木树、变量值、列表值、克隆体状态、扩展状态、项目元数据
- **修改方式**: 仅通过 RPC 由渲染进程请求修改
- **持久化**: 实时写入 .sf 文件 (SQLite)，每 30 秒自动保存，或用户手动 Ctrl+S

### 2.2 UI 状态

- **存储位置**: 渲染进程 Zustand Store
- **内容**: 当前选中的积木 ID、工具箱搜索词、面板展开状态、滚动位置、光标位置、调试控制台过滤条件
- **修改方式**: 本地直接修改，不通过 IPC
- **持久化**: 写入 IndexedDB，恢复上次会话的 UI 布局

## 3. 同步机制

- **扩展进程 → 渲染进程**: 通过 `project/state` 推送状态补丁 (仅变更的变量/列表)，而非全量状态。绘制指令通过 `render/commands` 每帧推送。
- **渲染进程 → 扩展进程**: 通过 `block/update`、`variable/set` 等 RPC 请求修改。每次请求有唯一 id，扩展进程返回确认。

## 4. 离线场景

- 用户离线时，渲染进程的修改暂存在操作日志 (IndexedDB)，恢复连接后批量重放。
- 重放期间若产生冲突，以服务器版本为准 (或扩展进程当前状态)，用户被提示手动解决。
